# nz.ua — автоматизація журналу вчителя

[English](README.md) · **Українська**

Створює стовпчики уроків у електронному журналі [nz.ua](https://nz.ua) за розкладом,
описаним у `schedule.yaml`. Один запуск закриває один місяць: 23 уроки фізики
і 3 уроки астрономії — 26 стовпчиків.

Для кожного уроку скрипт відкриває діалог «Додати стовпчик», ставить тип «Поточна»,
дату першого такого дня в місяці, повторення «щотижня до кінця місяця», номер уроку
і кабінет. Решту тижнів місяця добудовує сам сайт.

## Встановлення

```bash
pip install -e .          # ставить пакет nzua разом із залежностями
python -m playwright install chromium
cp .env.example .env      # і вписати туди NZ_LOGIN та NZ_PASSWORD
```

Без `pip install -e .` команда `python -m nzua` не побачить пакет: код лежить
у `src/`, а не в корені.

`.env` і збережена сесія `storage_state.json` у git не потрапляють.

## Використання

Усі команди з поясненнями, порядком роботи і прикладами:

```bash
python -m nzua --help
python -m nzua <команда> --help
```

```bash
# Подивитись, що буде створено, нічого не змінюючи
python -m nzua add-columns --month 2026-09 --dry-run

# Розвідка: пройти сайт разом зі скриптом, зібрати розмітку (один раз)
python -m nzua recon

# Створити стовпчики за вересень
python -m nzua add-columns --month 2026-09

# Обмежитись одним журналом
python -m nzua add-columns --month 2026-09 --subject Фізика --class 9-А

# Планування з .docx у planning/*.yaml (раз на семестр)
python -m nzua import-planning

# Теми уроків: усі 11 журналів, по 3 уроки в кожному
python -m nzua fill-topics --count 3

# Теми уроків одного класу
python -m nzua fill-topics --subject Фізика --class 9-А --count 1

# Перевірити журнали: нумерація, теми, ДЗ. Нічого не змінює
python -m nzua check

# Вирівняти журнал по плануванню без питань (тільки вирівняти)
python -m nzua fill-topics --subject Фізика --class 9-А --resync

# Усе за місяць одразу: стовпчики для всіх класів, потім теми
python -m nzua run-month --month 2026-09 --count 3

# Домашні завдання: зібрати з журналів минулого навчального року (раз)
python -m nzua dump-homework

# Скопіювати ДЗ з 9-А у 9-Б і 9-В: зібрати з 9-А, далі звичайний fill-topics
python -m nzua dump-homework --from 9-А
python -m nzua fill-topics --class 9-Б --count 3
```

Порядок обов'язковий: блок тем показує рядки лише для вже створених стовпчиків,
тому `fill-topics` без `add-columns` не має що заповнювати. `run-month` робить
обидва кроки в одному сеансі браузера.

## Перевірка журналів

```bash
python -m nzua check                       # усі журнали
python -m nzua check --class 9-А           # один
```

Читає таблицю тем і друкує зауваження, нічого не змінюючи:

| Що | Коли це нормально |
|---|---|
| порожній рядок, а далі є заповнені | урок не відбувся |
| пропуск у нумерації (1, 2, потім 4) | коригування зробили руками |
| номер повторюється або йде назад | майже завжди помилка |
| тема не збігається з плануванням | клас пішов своїм темпом |
| ДЗ порожнє | ще не задано |

Нічого з цього не зупиняє `fill-topics`. Знайшовши розбіжність, він питає:

```
--- Фізика 10-А: 10 клас.docx
  рядків 13, заповнено 12
  Рядків, що не збігаються з плануванням: 8 (пропуск або зсув нумерації).
    Переписати журнал за плануванням? [т]ак / [н]і / [у]сі такі / [з]упинити:
```

«так» — журнал вирівнюється по плануванню: n-й рядок стає n-м уроком, дірка
забирає свій номер, а все нижче зсувається. Інакше номер після дірки довелось
би правити руками до кінця семестру. «ні» — журнал лишається як є, скрипт
просто дописує далі від найбільшого номера й порожні рядки в середині не
чіпає.

Вирівнювання не чіпає двох речей: рядків після останнього заповненого (це
уроки, яких ще не було) і теми, яку ти дописала сама — «Вступний інструктаж.
Електричний струм.» під тим самим номером лишається.

`--resync` робить те саме без питання, тільки вирівнювання, нових уроків не
пише (якщо не задати `--count`).

## Домашні завдання

`fill-topics` пише в поле «Домашнє завдання» те, що лежить у `homework/`.
Порожньо — рядок пишеться без ДЗ, як раніше; це не помилка.

Наповнює цю теку `dump-homework`. Вона читає таблицю тем готових журналів і
складає пари «номер уроку, тема, домашнє завдання» у файл на паралель —
`homework/physics-9.yaml` поряд із `planning/physics-9.yaml`. Файл читається і
правиться руками.

```bash
python -m nzua dump-homework --semester-list  # які семестри є в акаунті
python -m nzua dump-homework --dry-run        # показати зібране, файлів не чіпати
python -m nzua dump-homework                  # обидва семестри минулого року
python -m nzua dump-homework --semester "2025-2026 [1]"
python -m nzua dump-homework --from 9-А,9-Б,9-В  # поточний семестр, ці класи
```

Паралель, а не клас: торішній 9-Б і цьогорічний 9-А — різні класи з одним
плануванням, тому ДЗ у них спільне. Урок шукається за номером **разом із**
темою: «Розв'язування задач.» трапляється в плануванні десятки разів із різним
ДЗ, і самої теми замало. Приписка з одного боку не заважає — «Вступний
інструктаж. Електричний струм.» і «Електричний струм.» під тим самим номером
вважаються одним уроком. Якщо планування перенумерували, підходить і тема,
яка в сховищі одна-єдина, але вже тільки за точним збігом.

Другий прохід дописує ДЗ у рядки, де тема вже стоїть, а ДЗ порожнє — теми в
9-Б і 9-В, заповнені до того, як 9-А віддав свої завдання. Тема й номер при
цьому не чіпаються. `fill-topics --count 0` робить лише цей прохід: нових тем
не пише, тільки дозаписує ДЗ.

### Семестр — стан сесії, не вкладки

`dump-homework` перемикає семестр через шапку сайту, а це змінює його **для
всього акаунта**. Семестр завжди повертається на місце, навіть коли запуск
упав. На додачу `add-columns` і `fill-topics` перед першим записом перевіряють,
що вибраний семестр позначений «(поточний)», і зупиняються, якщо ні: інакше
стовпчики пішли б у минулий рік.

Браузер завжди відкритий і видимий — видно кожну дію.

### Який браузер

Скрипт працює у звичайному Chrome вчителя, а не в окремому автоматизованому
браузері: запускає Chrome із портом налагодження 9222 на профілі
`.browser-profile-cdp/` (або під'єднується до вже запущеного), і Playwright
керує вкладкою, яку видно на екрані. Вхід в акаунт лишається у профілі, тож
логінитись треба один раз.

Браузер, запущений самим Playwright (`--browser launch`), сайт зустрічає
перевіркою «Підтвердьте, що ви людина», тому режим за замовчуванням —
`attach`. `launch` лишено для діагностики.

## Розклад

`schedule.yaml`. Кабінет за замовчуванням дорівнює назві класу; якщо колись
відрізнятиметься, до конкретного уроку додається поле `cabinet:`.

| День | Уроки |
|---|---|
| Понеділок | 1 — 10-Б, 2 — 11-А, 3 — 9-А, 4 — 10-А, 5 — 11-В (астрономія), 6 — 9-Б |
| Вівторок | 1 — 10-Б, 2 — 9-В, 3 — 11-А (астрономія), 4 — 9-В, 5 — 10-А, 7 — 9-Б |
| Середа | вільна |
| Четвер | 1 — 10-Б, 2 — 9-А, 3 — 9-Б, 4 — 9-В, 5 — 11-Б (астрономія), 6 — 11-Б, 7 — 8-Б |
| П'ятниця | 1 — 11-А, 2 — 9-А, 3 — 11-Б, 4 — 11-А, 5 — 10-А, 6 — 11-Б, 7 — 8-Б |

Канікули й святкові дні не враховуються: зайвий стовпчик простіше видалити вручну,
ніж підтримувати календар вихідних.

## Структура

| Файл | Призначення |
|---|---|
| `schedule.yaml` | розклад уроків |
| `src/nzua/schedule.py` | модель розкладу і вся арифметика дат |
| `src/nzua/browser.py` | запуск Chromium, збереження сесії логіну |
| `src/nzua/selectors.py` | **усі** селектори сайту — єдине місце, яке правиться при зміні верстки |
| `src/nzua/recon.py` | збір розмітки сайту для написання селекторів |
| `src/nzua/planning.py` | розбір .docx планування у `planning/*.yaml` |
| `src/nzua/homework.py` | сховище домашніх завдань: `homework/*.yaml` |
| `src/nzua/topics.py` | таблиця тем, діалог «Домашнє завдання», перевірка `check` |
| `src/nzua/cli.py` | розбір команд |

## Як воно знаходить журнали

Ідентифікатори журналів змінюються щосеместру, тому не зашиті в код: на
початку кожного запуску читається `/journal/list` і будується мапа
«предмет + клас → адреса». Підгрупи (`9-Б(1)`) нормалізуються до назви класу;
якщо під одну пару підпадає кілька журналів, скрипт не вгадує, а зупиняється.

## Як розпізнаються дублікати

Шапка журналу показує лише число, а місяць — один раз, на першому стовпці
місяця (`1 Вер.`). Дати відновлюються з цієї послідовності, відштовхуючись від
дати початку семестру.

Порівнюється не наявність, а кількість: 9-В має фізику двічі у вівторок
(2-й і 4-й уроки), отже два стовпці на вівторок — це правильно, а третій — ні.
При розбіжності скрипт зупиняється і питає: пропустити, додати все одно,
пропускати всі такі, чи зупинитись.
